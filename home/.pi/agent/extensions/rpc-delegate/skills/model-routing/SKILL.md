# Model routing

Pick `provider` + `model` for `rpc_delegate_task`. Procedure,
failure classes, telemetry schema: `references/model-routing.md`.
Roster (rankings, routing policy, open/closed metadata, hand-curated):
`assets/roster.json` (tracked).
Per-machine verdicts: `assets/verdicts.json` (probe-regenerated by
`scripts/check.mjs`, gitignored). Effective thinking maps:
`assets/thinking-levels.json` (derived by `scripts/derive.mjs` via
RPC `get_state`, zero tokens; gitignored). Paths + probe command:
`assets/paths.json`.

**When to derive** (`node scripts/derive.mjs`): `--status` / `--lint`
say so (record missing or ≥ 30 d stale, roster id not derived,
managed-block DRIFT); after roster edits on thinking models; after
any `~/.pi/agent/models.json` edit (`--dry-run` verifies drift;
`--status` reports it without spawning).

## Procedure

1. **Classify** the task: one of 8 archetypes (roster); none fits →
   research vs code vs judgment.
2. **Hard filters** (live list + model store): id present in the
   live provider list (`node scripts/check.mjs --live`; store ⊇ live
   — the stale store keeps retired ids, so the live list is
   availability truth; `retired` verdict = out; fail open on no
   key/network — fall back to store), then store (`~/.pi/agent/models-
   store.json`): contextWindow ≥ corpus, `image` in `input` for
   vision, `maxTokens` ≥ output, cost ceiling. Absent
   `maxTokens`/`reasoning` = fail. Fail = out, regardless of rank.
3. **Verdict eligibility + route preview**: build the candidate list
   from `assets/verdicts.json` — only `verdict: "reachable"` entries
   that passed step 2. Non-reachable or missing verdict = not eligible —
   probe (step 5) or skip. Stale = cadence due (50 telemetry rows or 30
   days since `revised`): check with `node scripts/check.mjs --status`
   (read-only); refresh with a default `node scripts/check.mjs` run.
   Preview the computed order with
   `node scripts/route.mjs --archetype "<name>"` (add
   `--min-context`, `--min-output`, `--needs-image` for hard filters).
   It is read-only and prints eligibility, gate state, and exclusion
   reasons.
4. **Apply routing policy** (`roster.policy`) to the eligible list.
   Preference never overrides step 2 or 3. `roster-order` uses `picks`
   then `alt`; `open-first` orders by the symmetric quality gate;
   `fallback: frontier` retries once on an open-model failure. Ordering,
   gate, and retry rules: `references/model-routing.md`
   §Open-weight preference policy.
5. **First-time model — probe first** (its provider):
   `pi --no-session --provider <provider> --model <id> --print "ok"`
   (~10 s, ≤ ~$0.04). `--no-session` mandatory — no stray session files.
   Blocked = out. Probe ≠ delegation path: see `references/model-routing.md`
   §Known gaps.
6. **High stakes / novel task:** A/B parallel — two cheap delegations of
   the same task, compare artifacts, keep the winner. Do this before
   trusting an open-first slot on a new task shape.
7. **Pin `provider` AND `model`** — never model alone.
8. **`tools` allowlist per archetype:** research children read-only; code
   children full set.
9. **Telemetry:** pass `archetype` on every `rpc_delegate_task` call
   — the extension writer records it plus `source`, `artifactPolicy`,
   and one row per return (settled, rejected, in-flight).
   Verify the row landed — the writer is best-effort (silent failure
   possible) and the running session may predate an extension edit
   (restart pi to pick up extension code). Rankings are priors (n=1
   origin) — re-rank review only via telemetry flags (`node
   scripts/check.mjs --status`; writer rows only), never gut.

Batched micro-judgments (classify / score / yes-no, many items) →
`typesafe_evaluate`, not delegation.

## Fallback (unknown or renamed models)

Order of authority: **mechanical filters → probe → name class → roster
→ gut never.**

- Name class: `nano|mini|luna|flash|lite|haiku` → triage / bulk / drafts;
  `sol|pro|opus|astra|max|ultra` → judgment / synthesis;
  `codex|coder|code|build` → greenfield code; `jev` → typesafe.
- Store: `reasoning: false` or `null` → not proven for tool loops;
  `thinkingLevelMap` high+ → judgment-capable; map lacking an `off`
  key → 400 risk (`--lint` checks key presence only — value may be
  `null` or `"none"`; regenerate patches with
  `node scripts/derive.mjs` — it rewrites the skill-managed
  `modelOverrides` block in `~/.pi/agent/models.json`); cost all-zero →
  free tier → 403.

## Guardrails

- `artifactPolicy: "artifacts"` for file deliverables; `"stopReason"` for
  prose.
- Free (cost-0) models: not delegation candidates (403/410 on this
  account).
- Open-first is a preference, not a filter. Hard filters and the
  reachable verdict still decide eligibility. Absent `modelMeta` =
  closed. The quality gate is symmetric: open and closed candidates are
  judged by the same `minArtifactRows`/`maxBrokenRate` budget.
- An open model in `never_delegate` is not a routing candidate; removing
  the contradiction is a roster edit, not a runtime override.
