# Model routing reference

Data + rationale for model-routing skill. Procedure lives in `../SKILL.md`.

Roster (rankings, alternatives, never_delegate) lives in
`../assets/roster.json` (tracked, hand-curated). Per-machine verdicts
live in `../assets/verdicts.json` (probe-regenerated by the script,
gitignored; written atomically — tmp + rename). Paths + probe command
live in `../assets/paths.json` (tracked; tilde paths;
`{provider}`/`{id}` placeholders); `--catalog` / `--models-config` /
`--telemetry` CLI flags override; unknown flags exit 2. Refresh
(probes roster, rewrites verdicts): `node ../scripts/check.mjs`; `--full`
additionally probes every first-party catalog model and persists
non-roster verdicts in the verdicts `catalog` section (a default refresh retains the
section; `--status` excludes hard-verdict catalog ids from
unprobed-new). Read-only cadence + re-rank flags + derivation state: `--status`
(degrades to a warning on a missing catalog; flags count writer rows
only; reports the thinking-map record — revised, age, roster coverage
— and managed-block drift via the shared policy, zero spawns).
Roster/verdicts/telemetry/class validation: `--lint` (catalog and
models.json degrade independently — a missing models.json skips only
the modelOverrides merge; a missing catalog skips capability lint).
Refresh aborts (exit 1, no verdicts write) when ≥ 25% of probes fail
to spawn — a broken probe harness never produces a clean-looking
refresh. Cross-provider catalog id collisions are reported (first
provider wins).

Thinking-map derivation: `node ../scripts/derive.mjs` (default) —
for every roster + first-party catalog id, spawn an RPC child
(`pi --mode rpc --no-session --no-extensions`, template in
`../assets/paths.json` `rpcCommand`) and read the effective
`thinkingLevelMap` from the `get_state` response (spawn + handshake
only — zero tokens, ~1-2 s per model). Persists
`../assets/thinking-levels.json` (per-machine, gitignored;
`thinkingLevelMap: null` = no map = no risk) and regenerates the
skill-managed `modelOverrides` block in `~/.pi/agent/models.json`
(ownership split below). `--dry-run`: no writes, exit 1 on models.json
drift. Fail-closed: ≥ 25% of children failing to spawn aborts without
a write. `--lint` validates the record (shape, `revised` staleness
≥ 30 d, roster coverage) and prefers it over the store+merge estimate
for roster effective-map checks. **When to derive**: `--status` /
`--lint` say so (record missing or ≥ 30 d stale, roster id not
derived, managed-block DRIFT); after roster edits on thinking
models; after any `~/.pi/agent/models.json` edit (`--dry-run`
verifies drift; `--status` reports it without spawning). The policy
(generated / retained / dropped / drift) is single-sourced in
`shared.mjs` — derive.mjs writes it, `--status` reports the same
computation, zero spawns.

Failure-class taxonomy (class values, probe + delegation patterns,
per-class samples) is single-sourced in `../scripts/classes.mjs` —
imported by `check.mjs` and by the rpc-delegate extension
(`model-routing-classes` file: dependency in the extensions
`package.json`). `--lint` asserts pattern-set agreement per shared
class and classifies one sample per class. Shared script helpers
(argument parsing, catalog flattening, first-party filter, probe
pool) are single-sourced in `../scripts/shared.mjs` — used by both
`check.mjs` and `derive.mjs`; they must never drift apart.

## Failure classes

Seven classes. Detection mechanism per class:

**Metadata-detected (store lint — never probe-classifiable):**

1. **thinking-map-400** — map lacking an `off` key + session default
   `thinkingLevel: "off"` can trigger upstream 400 (or clamp to a
   forced xhigh/max — cost inflation). Detected by
   `scripts/check.mjs --lint`, preferring the derived record
   (`assets/thinking-levels.json`, live RPC `get_state` truth) over the
   `models-store.json` + `models.json` `modelOverrides` estimate
   (key presence only; the value may be `null` or `"none"`);
   probe output cannot classify it (`classifyVerdict` has no
   pattern).

**Probe-classifiable (`scripts/check.mjs` `classifyVerdict` matches
probe output; probe recipe in `../SKILL.md` catches these directly):**

2. **access-403** — per-model access disabled. Access is per-model
   within a family; catalog presence proves nothing.
3. **free-tier-403** — cost-0 models are not delegation candidates on
   this account (probed: 6 of 11 cost-0 catalog entries free-tier-403;
   5 unprobed-new).
4. **endpoint-410** — endpoint unavailable/deprecated.
5. **param-400** — model rejects request parameter.
6. **unavailable-400** — provider reports model unavailable.

**Telemetry-only (delegation path; probes return `indeterminate`,
never this value):**

7. **other** — uncategorized delegation failure.

## Thinking-map derivation + ownership split

`derive.mjs` derives effective maps per model because no other
channel can: `pi --list-models` shows thinking yes/no only; `--print`
probes clamp unsupported levels silently; RPC `get_state` returns the
merged map (store + `modelOverrides`) — spawn + handshake only,
zero tokens (~1-2 s per model).

**models.json ownership split** (`~/.pi/agent/models.json`,
untracked, user file):

- **User-managed** — everything except the managed block: local
  provider definitions (ollama et al.) and all other keys are
  preserved verbatim. Deleting the whole file loses these — local
  providers are not the skill's to regenerate (documented user loss);
  `derive.mjs` then recreates the file with the managed block only.
  An unparseable models.json is never clobbered (loud failure).
- **Skill-managed** — `providers.<defaultProvider>.modelOverrides`,
  a generated artifact, regenerated on every derive run. Policy: every
  roster id whose store `thinkingLevelMap` exists but lacks an `off`
  key gets the canonical patch `{thinkingLevelMap: {off: null}}`
  (on this roster: the claude family — opus-5-5 / sonnet-5-5 /
  haiku-5-5 picks, plus never_delegate opus-5 / opus-4-6 / opus-4-7 /
  sonnet-4-6). Prior managed entries that still satisfy the patch
  condition (id in catalog, store map still lacks `off`) are retained
  verbatim — non-canonical shapes reported; stale ones (model gone,
  store map gained `off`) are dropped, each with its reason. Deleting
  the block self-heals on the next run; regeneration is idempotent
  (canonical compare — no rewrite when unchanged).

Per-model hand management of the managed block is off — hand-added
entries survive only while the patch condition still holds, and every
derivation decision is reported (generated / retained / dropped).

## Telemetry

One JSONL row per `rpc_delegate_task` terminal return (settled,
param-rejected, or in-flight), auto-appended by the extension at:
`~/.pi/agent/extensions/rpc-delegate/telemetry.jsonl`

```json
{
  "ts": "<iso>",
  "source": "rpc-delegate",
  "archetype": "Greenfield code / big feature",
  "provider": "opencode",
  "model": "gemini-3.1-pro",
  "stopReason": "stop",
  "stallHit": false,
  "failureClass": null,
  "tokensIn": null,
  "tokensOut": null,
  "costUsd": 0.0983,
  "runSecs": 40,
  "artifactOk": true,
  "artifactPolicy": "stopReason",
  "note": "one-line takeaway"
}
```

`failureClass`: `thinking-map-400 | access-403 | endpoint-410 |
free-tier-403 | param-400 | unavailable-400 | other`.
`source` is the provenance marker (`rpc-delegate`); rows without it
are pre-writer legacy — summarized by `--lint`, excluded from re-rank
flags. `archetype` comes from the `archetype` tool param and may be
null when omitted. `stopReason` domain:
`stop | success | error | aborted | pending | length | deferred` —
novel values warn, malformed values fail lint. Rejected and in-flight
rows carry `note` prefixes (`rejected:` / `tool return in flight`)
with null run facts.

Nulls mean unknown.

Schema above is illustrative. `node ../scripts/check.mjs --lint`
validates live rows (hard keys always; nullable keys after first
appearance — pre-adoption legacy rows tolerated and summarized) plus
roster/verdicts consistency — the script is the enforcement, this prose
is not.

### Cadence

Review route marks when either threshold hit:

- 50 telemetry rows since last verdicts revision, or
- 30 days since last verdicts revision.

`node ../scripts/check.mjs --status` (read-only) reports cadence from
telemetry vs the `revised` field in `assets/verdicts.json`; a default run refreshes
(re-probes, rewrites verdicts, bumps `revised` — resets the row
counter).

Re-rank review path: `--status` flags any model (or archetype × model
cell) with ≥ 3 artifact-policy writer rows (`source: rpc-delegate`;
`artifactOk` true or false — artifact-less runs under `artifactPolicy:
"stopReason"` are null and excluded; pre-writer legacy rows carry no
`source` and are excluded) and ≥ 1 broken — demotion candidate.
Rankings are priors (n=1 origin, single task shape); no
promotion/demotion without these flags.

## Mechanism

Hybrid split:

- **Judgment — agent-side:** skill procedure (`../SKILL.md`) + tracked
  roster (`../assets/roster.json`) + local verdicts
  (`../assets/verdicts.json`, per-machine).
- **Facts — extension-side:** telemetry append + failure typing in result
  path. Lifecycle machine untouched.

## Known gaps

- Telemetry append is best-effort with a silent catch; sessions started
  before an extension code edit run the old code — their delegations
  write old-format rows until pi restarts.
- Probe ≠ delegation path: the probe spawns plain `--print`; the RPC
  child runs `--mode rpc` with the child's default tools (an explicit
  `tools` allowlist narrows them). Probe-pass does not prove
  delegation-path safety. Effective thinking maps are no longer a
  probe gap — `derive.mjs` reads them via `get_state` on the same RPC
  spawn path delegations use; the remaining probe↔delegation
  difference is the tool loop itself (probe↔delegation parity for
  failure surfaces is untested).
- The roster covers 29 of 85 first-party catalog models; `--status`
  lists unprobed ids; a `--full` run (~85 probes, ~$3, ~10 min)
  populates the verdicts `catalog` section for the rest; the name-class fallback is
  prose-only.
- Verdicts are probe-time snapshots; per-model access can
  change between probes.
